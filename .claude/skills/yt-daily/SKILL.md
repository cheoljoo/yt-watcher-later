이 프로젝트(`~/code/yt-watcher-later`)의 DB 에 쌓인 **Claude 처리 대기 작업**을 이 세션 하나에서 끝까지 처리한다.
수집·시세 조회·DB 저장은 `work.py` 가 하고, 당신은 작업마다 JSON 한 개를 만들어 제출하는 일만 한다.

## 반복 절차

1. `uv run work.py next` 를 실행한다. 출력은 JSON 한 줄이다.
   - `"done": true` 이면 **즉시 종료**한다. 마지막에 한 줄로 "끝: 사유"만 출력한다.
   - 아니면 `task`, `kind`, `input_file`, `schema_file` 이 있다.
2. `input_file` 을 Read 로 읽는다 (`allow_large: true`). 파일에는 `# 지시`(무엇을 만들지)와 `# 입력`이 있다.
3. 지시대로 결과 JSON 을 만든다. 형식은 `schema_file` 의 JSON Schema 를 따른다.
   (같은 kind 의 스키마를 이미 읽었고 기억이 분명하면 다시 읽지 않아도 된다. 제출이 검증에서 실패하면 그때 읽는다.)
4. 결과 JSON 을 Write 로 `data/_work/out/TASK_ID.json` 에 저장한 뒤 제출한다:

   `uv run work.py submit TASK_ID --file data/_work/out/TASK_ID.json`

5. 출력이 `OK ...` 이면 1번으로 돌아간다. 스키마 검증 실패 메시지가 나오면 고쳐서 한 번만 다시 제출한다.
   그래도 실패하면 `uv run work.py skip TASK_ID --reason "이유"` 후 1번으로 간다.

## 규칙

- **허용된 명령 외에는 절대 실행하지 않는다.** `python3`, `grep`, `sqlite3` 등으로 DB·코드를 들여다보지 않는다(거부되면 세션이 멈춘다). 형식이 궁금하면 `schema_file` 만 Read 하고, 모르겠으면 `uv run work.py skip TASK_ID --reason "이유"` 후 다음 작업으로 간다. `done` 이 나올 때까지 계속한다.

- **모든 명령은 포그라운드로 실행하고 결과가 나올 때까지 기다린다.** 백그라운드로 돌리거나 "확인 중"이라고만 답하고 턴을 끝내지 않는다. `done` 이 나오기 전에는 응답을 끝내지 않는다.

- 작업 사이에 설명·요약·확인 질문을 하지 않는다. 도구 호출만 이어서 한다. (토큰 절약)
- 입력에 없는 사실을 지어내지 않는다. 지시문에 적힌 제약(날짜 형식, 열거값, name 은 입력 그대로 등)을 지킨다.
- 도구는 `uv run work.py ...`, Read, 그리고 `data/_work/out/` 아래에 결과를 쓰는 Write 만 쓴다. `claude` 를 다시 실행하거나 DB 직접 접근은 하지 않는다.
- **웹 검색은 `check`(확인 항목 판정)와 `events`(주별 큰 일 조사)·`rich`(부자들 투자 방법) 작업에서만, 그리고 반드시 쓴다.** (Claude: WebSearch·WebFetch / agy: search_web·read_url_content.) 다른 kind 에서는 쓰지 않는다.
- 작업은 서로 독립이다. 앞 영상의 내용을 다음 영상 분석에 섞지 않는다.
- kind 별 요령:
  - `video`: 자막은 자동 음성인식이라 오인식이 있을 수 있다. 문맥으로 보정하되 확신 없는 고유명사는 피한다.
  - `check`: 확인일이 어제까지인 모든 항목을 판정한다(입력의 모든 id). **항목마다 판정 전에 웹 검색으로 최신 보도·공시·시세를 찾는다** — 당신의 기억은 낡았을 수 있어서 '아직 ~하지 않았다'고 기억만으로 단정하면 안 된다(예: 이미 상장·발표·인상이 끝난 일일 수 있다). 검색어에 대상 이름+연월(영문명·티커 포함)을 넣고, 결과가 엇갈리면 가장 최근 날짜의 1차 출처(공시·거래소·공식 발표·통신사)를 따른다. 업로드일→확인일(→오늘) 사이 변화를 `since_upload` 에, 근거 출처(매체·기사 날짜)를 `reason` 에 쓴다. 검색 도구가 막혔거나 근거를 못 찾았을 때만 `unknown` + 어디서 확인할지를 `result` 에 쓴다.
  - `track`: 영상마다 배울 점·확인 항목에서 숫자로 꾸준히 볼 지표만 뽑는다. 해당이 없으면 빈 배열이 정답이다. video_id 는 입력 그대로 모두 반환한다.
  - `opinion`: 시청자의 '나의 의견'에 대한 AI 의견(reply)을 쓴다. 동의할 부분과 보완할 부분을 나누고 영상 요약에 없는 사실은 지어내지 않는다.
  - `events`: 입력의 각 `week`(월요일 날짜)마다 그 주(월~일)에 **한국(kr)·미국(us)·세계(world) 각각에서 경제에 가장 큰 영향을 준 일 1개씩**(금리·경제지표·시장 급등락·무역/경제정책·기업 실적, 그리고 전쟁·정치·재난이라도 유가·물가·환율·증시에 크게 영향을 준 일은 포함하고 그 영향을 숫자로 쓴다)을 **웹 검색으로 확인해** 쓴다(date 는 그 주 안, detail 은 한 문장, world 는 kr·us 와 겹치지 않게). 검색에서 확인한 사실만 쓰고, 큰 일이 없거나 확인되지 않은 지역은 date·title·detail 을 빈 문자열로 둔다. 입력의 모든 week 를 한 번씩 그대로 반환한다.
  - `rich`: 오늘 웹을 검색해 한국 부자들이 쓰는 투자 방법을 지시문의 자산 구간(tier)별 개수대로 찾는다(보통 10억~100억 2개 + 100억 초과~300억 1개, 한국 사람의 해외 부동산·주식·금융 투자는 포함, 외국 부자 이야기는 제외). 검색에서 확인한 내용만 쓰고, url 은 실제로 확인한 원문 주소여야 하며 입력의 '이미 수집한 항목'과 겹치지 않게 한다. summary 는 3~4문장.
  - `checkfill`: 각 예상에 대해 맞을 때(if_right)/틀릴 때(if_wrong) 시청자가 할 행동을 쓴다.
  - `enrich`/`map`/`meaning`/`phase`: 지시문의 항목 수와 name/id 를 입력과 정확히 일치시킨다. 입력의 모든 항목에 대해 결과를 낸다.
